# Edge Cases & Error Conditions

Documents how the system handles boundary inputs and failure modes.
Each row is verified against source code; implementation citations reference `file:function`.

| Scenario | Handling | Implementation |
|---|---|---|
| User uploads a scanned/image-only PDF (no text layer) | `pdfplumber` and `pypdf` both return empty strings for image-only PDFs; `parse_resume` detects the empty result and raises `ValueError("Could not extract any text from this resume. Make sure it is not a scanned image-only PDF.")`. The API endpoint catches this and returns HTTP 422. | `jobspy/nlp/resume_parser.py:extract_text_from_pdf` (text extraction); `jobspy/nlp/resume_parser.py:parse_resume` (empty-text guard at line 1092–1096); `api/main.py:upload_resume` (catches `Exception`, returns 422) |
| User uploads a non-PDF/non-DOCX file (e.g., `.jpg`, `.txt`) | The upload endpoint inspects the file extension before any parsing. If the extension is not `.pdf` or `.docx`, it immediately raises HTTP 400 with `"Only PDF and DOCX files are supported."` No file is saved to disk. | `api/main.py:upload_resume` (extension check at lines 403–405) |
| No resume uploaded when calling `POST /api/cover-letter/{id}` | `get_resume_profile` returns `None` when no profile exists; the endpoint checks for this and raises HTTP 404 with `"No resume uploaded. Please upload your resume on the Profile page first."` | `api/main.py:create_cover_letter` (lines 513–518) |
| No resume uploaded when calling `GET /api/jobs/{id}/match` | Same guard pattern: `get_resume_profile` returns `None`, endpoint raises HTTP 404 with the same "No resume uploaded" message before attempting any scoring. | `api/main.py:get_job_match` (lines 317–322) |
| Claude API key missing at runtime | `generate_cover_letter` reads `ANTHROPIC_API_KEY` from the environment; if absent it raises `ValueError("ANTHROPIC_API_KEY environment variable not set. Add it to your .env file or export it in your shell.")`. The API endpoint catches `ValueError` and returns HTTP 500 with that message. | `jobspy/nlp/cover_letter.py:generate_cover_letter` (lines 79–84); `api/main.py:create_cover_letter` (lines 541–542) |
| A single platform scraper fails/times out during a multi-platform scrape | Each scraper runs in its own `ThreadPoolExecutor` thread. The `as_completed` loop wraps `future.result()` in a `try/except Exception`; on failure it logs the error and substitutes `JobResponse(jobs=[])` for that platform, allowing the other scrapers' results to proceed normally. | `jobspy/__init__.py:scrape_jobs` (lines 126–133) |
| Zero matches for a search query | `scrape_jobs` returns an empty DataFrame; `save_jobs` returns 0 immediately; the scrape endpoint returns `{"total_found": 0, "total_saved": 0, "jobs": []}`. `query_jobs` likewise returns an empty DataFrame when no DB rows match, and `get_jobs` returns `{"total": 0, "jobs": []}`. | `jobspy/database.py:save_jobs` (early return at line 187–188); `jobspy/database.py:query_jobs` (empty DataFrame at lines 330–331); `api/main.py:scrape` and `api/main.py:get_jobs` |
| Duplicate job from a re-scrape (same `job_id`) | `save_jobs` performs an upsert: it fetches the existing row by primary key and, if found, updates all mutable columns (including `last_seen_at`) while preserving `first_seen_at`. No duplicate row is created. | `jobspy/database.py:save_jobs` (upsert logic at lines 210–217) |
| Job in DB with `None` description (skill extraction target) | `extract_skills` guards its first line with `if not description or not description.strip(): return {"required": [], "preferred": []}`. `extract_skills_bulk` coerces `None` to `""` before passing it in. The cover letter generator also coerces `None` to `""` via `(job.get("description") or "")[:3000]`. | `jobspy/nlp/skill_extractor.py:extract_skills` (line 104–105); `jobspy/nlp/skill_extractor.py:extract_skills_bulk` (line 151); `jobspy/nlp/cover_letter.py:generate_cover_letter` (line 97) |
| Non-ASCII unicode in resume (em-dashes, smart quotes, bullet characters) | `_clean_text` applies `_normalize_unicode` to every non-ASCII character via a regex substitution. The mapping converts em-dashes (`\u2013`, `\u2014`) → `-`, smart quotes (`\u2018`–`\u201D`) → `'`/`"`, common bullet characters (`\u2022`, `\u25A0`, `\u25CF`) → `-`, and non-breaking spaces → ` `. Characters not in the mapping become a space. | `jobspy/nlp/resume_parser.py:_clean_text` (lines 409–420); `jobspy/nlp/resume_parser.py:_normalize_unicode` (lines 423–432) |
| International location search (e.g., "Mumbai, India" or "Dubai, UAE") | `select_platforms` lowercases the location string and checks it against `REGION_PLATFORM_MAP`. "mumbai" appends `["naukri"]`; "dubai" and "uae" each append `["bayt"]`. These are unioned with the default set `[linkedin, indeed, glassdoor, google]` so region-specific boards are automatically included without duplicate entries. | `jobspy/platform_selector.py:select_platforms` (lines 64–70); `jobspy/platform_selector.py.REGION_PLATFORM_MAP` (lines 14–46) |
| Resume with non-standard section header (e.g., "Career Highlights" or "Professional Highlights" instead of "Experience") | `SECTION_SYNONYMS` routes `"career highlights"` and `"professional highlights"` → `"experience"`, so the content is parsed by the date-anchor strategy as structured job entries. `"highlights"` alone remains → `"summary"` as the safe default for genuinely ambiguous usage (could be a bullet-list narrative rather than a job history). The state-machine in `_is_section_header` performs a layer-1a exact lookup after lowercasing and stripping punctuation. | `jobspy/nlp/resume_parser.py:SECTION_SYNONYMS` (lines 45–47); `jobspy/nlp/resume_parser.py:_is_section_header` (layers 1a–1b, lines 458–467); `jobspy/nlp/resume_parser.py:segment_sections` |
